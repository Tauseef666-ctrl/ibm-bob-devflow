## What is still broken

`POST /api/analysis/start` returns **500** on Vercel, so the core product
feature does not work when deployed. Reproduced locally only when
`sample-project/` is absent from the bundle, which is what Vercel ships.

Findings so far, not yet fixed:

1. `sample-project/` is not in the function bundle, so
   `backend/src/routes/analysis.js:16` (`../../../sample-project`) resolves to
   nothing. Locally this degrades silently to **3 findings instead of 21**,
   which is worse than an error because it looks like a successful run.
2. `backend/src/modules/buildRelease.js:142` shells out to `npm install`.
3. `backend/src/modules/testHealth.js:139` shells out to `npm test`.
4. `backend/src/remediation/remediator.js:75,107,121,139` writes files, and the
   serverless filesystem is read-only.
5. Function `maxDuration` is 30s; analysis with two npm shell-outs will exceed it.

Not yet identified: the exact throw causing the 500. `vercel logs` needs a
linked project, and runtime logs were not readable through the REST API tried
so far. Next step is `npx vercel link` then
`npx vercel logs ibm-bob-devflow --follow`, or adding a temporary error log.
